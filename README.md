# NEURON

[English](README.en.md) · 简体中文

一个用来收集链接、整理笔记的个人知识库。页面采用浅色布局、彩色领域标签和卡片视图。首次打开时没有预置内容，你可以从第一条收藏开始。

## 可以做什么

- 保存文章、帖子、项目链接和自己的笔记。
- 新建知识领域，设置颜色，再用标签补充其他维度。
- 搜索标题、标签和笔记，切换卡片或列表视图。
- 在知识图谱中按领域浏览内容。
- 标记精选，导入或导出 JSON 备份。

预置分类包含算法、运控、VLA、世界模型、硬件、系统等。它们是分类选项，没有附带个人资料。

## 本地运行

需要 Python 3。在仓库目录运行：

```sh
python3 -m http.server 4317 --bind 127.0.0.1 --directory docs
```

打开 <http://127.0.0.1:4317>。项目使用 HTML、CSS 和 JavaScript，无需安装前端依赖或执行构建。

## 部署到 GitHub Pages

1. 将这些文件上传到自己的仓库。
2. 打开仓库的 **Settings → Pages**。
3. 在 Source 中选择 **Deploy from a branch**。
4. 选择 `main` 分支和 `/docs` 目录，保存。
5. 等待 GitHub 显示站点地址。

之后更新 `docs/` 内的文件，GitHub Pages 会重新发布。部署到子路径时，页面使用相对资源路径。

## 日常使用

点击“收藏内容”，填写链接、标题、领域和笔记。需要新的分类时，点击侧栏“新建领域”，输入名称并选择颜色。领域最多支持 60 个自定义项，名称最长 24 个字。

领域用于主要分类；标签用于交叉维度。例如，一条资料可以属于“机器人感知”领域，同时带有“论文”和“待读”标签。

快捷键 `Ctrl/Cmd + K` 或 `/` 可聚焦搜索框。

## 数据与备份

收藏、精选和自定义领域保存在当前浏览器的 `localStorage`。内容不会自动上传到 GitHub，也不会在设备间同步。清除浏览器数据会删除这些本机记录。

使用页面底部的“导出 JSON”保存备份，再通过“导入备份”迁移到另一个浏览器。导入文件上限为 5 MB、500 条收藏。不要把个人备份提交到公开仓库。

本仓库从空白内容开始，不包含个人 Notion 页面链接、账号凭据或收藏记录。来源图标仅用于识别平台，不表示与平台有合作关系。

## 接入 AI 分析

1. 打开侧栏“AI 设置”。
2. 填写完整的 API 请求地址，例如 `https://你的服务域名/v1/chat/completions`。
3. 填写服务商提供的模型 ID 和 API Key。
4. 可点击“测试连接”，然后点击“应用配置”。测试会发送一条短消息，可能计费。
5. 打开一条收藏，点击“AI 分析”。粘贴正文、评论或笔记，选择分析方式，再点击“发送文字并分析”。
6. 核对输出后点击“保存分析”。结果单独保存，不覆盖原有笔记。

接口采用 Chat Completions 格式：请求包含 `model`、`messages` 和 `stream: false`，响应读取 `choices[0].message.content`。可接入提供这一兼容接口的服务商或自建网关。[DeepSeek 的接口文档](https://api-docs.deepseek.com/api/create-chat-completion/)提供了这种格式的示例。模型名称和地址以你使用的服务商文档为准。

地址必须使用 HTTPS，以 `/chat/completions` 结尾。密钥通过 Bearer 认证发送；无密钥的自建网关可留空。当前不支持原生 Anthropic Messages、Gemini 或 Responses 格式。

API Key 默认保留在页面内存中。启用下方的“本机加密保存”后，刷新时可用口令恢复。地址和模型 ID 保存在本机。JSON 备份包含已保存的分析，不包含 API 配置或密钥。文字与密钥直接发送到你填写的服务地址，使用前请确认该地址可信。

GitHub Pages 是静态托管。浏览器直连需要服务端允许 CORS（跨域请求）。如果服务不允许，可以填写自己管理的 HTTPS 兼容网关地址。不要把长期使用的共享密钥写进源码；需要隐藏服务商密钥时，应由自己的后端保管。

每次最多输入 30,000 字符，请求在 90 秒后超时。页面支持取消请求，取消后服务商仍可能对已经处理的请求计费。返回内容按纯文本显示；输出截断时会提示。

本功能分析你提供的文字，不会自动读取文章链接、图片或评论区。Notion 不是运行依赖。自动采集和跨设备同步仍需另外接入后端与数据库。

## 账户与密钥保存

右上角“登录”使用 Firebase Google 登录。登录状态在刷新后保留。当前收藏仍保存在本机，登录不会自动同步收藏。

AI 设置提供“本机加密保存”：

1. 填写 API 地址、模型 ID 和 API Key。
2. 设置 12–256 个字符的解锁口令，点击“加密保存到本机”。
3. 刷新后，在 AI 设置输入口令，点击“解锁已保存密钥”。

密钥及其接口配置使用 AES-GCM 加密。口令经 PBKDF2-SHA-256（600,000 次）派生加密密钥。每次保存使用随机盐和随机 IV。口令不存储。忘记口令后，需要删除旧记录并重新填写 API Key。加密记录不包含在 JSON 备份中。清理浏览器数据会删除它。

“清除密钥”清除当前页面内存；“删除本机密钥”还会删除加密记录。解锁期间，页面脚本可以使用明文密钥。此功能不等于服务器密钥托管，也不随 Google 账户同步。

本实例复用 `i2dl-c79f8` 的公开 Firebase Web 配置。复用模板时，修改 `docs/account.js` 为自己的项目配置，在 Firebase 启用 Google 登录，并授权自己的域名。当前代码不读写 I2DL 的 Firestore 学习进度。

微信扫码登录尚未配置。它需要微信开放平台网站应用和后端回调服务。云端密钥托管也尚未启用。若使用 Firebase Cloud Functions，需要 Blaze 方案。

参考：[Firebase Google 登录](https://firebase.google.com/docs/auth/web/google-signin)、[Cloud Functions 部署条件](https://firebase.google.com/docs/functions/get-started)。
